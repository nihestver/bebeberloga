# S4 — спайк MLS Delivery Service на Go: состояние

Промпт: `docs/prompts/S4-mls-ds.md`. Ветка `spike/S4-mls-ds`. Отчёт — `REPORT.md`, решение — `docs/adr/0018-spike-s4-mls-ds.md`.

## Сделано

- `ds/` (Go): прототип DS на Postgres — строка группы блокируется первой в обоих режимах, счётчик лимита — вне строки группы, разнесён на строку заявок и строку commit-ов; склад KeyPackage с проверкой подписей, capabilities, расширений листа, срока (нижняя и верхняя границы) и общим пространством HPKE-ключей, резервирование пакета с самым поздним сроком; сериализация handshake по группе (advisory lock или блокировка строки); commit только для текущей эпохи, повтор принятого commit-а идемпотентен; предложения Add/Remove от external sender с привязкой к устройству в `authenticated_data` и батчингом («сразу», интервал, `max-batch`, «фронт + батч»); дельта состава в `authenticated_data` commit-а и карта листьев; заявка на вход перепроверяет членство под строкой группы, Remove участника заменяет его заявку; Remove ждёт подтверждения commit-ом другого устройства (эвристика, не защита — ADR-0018 п. 2); отмена опубликованного Add — через «принять и сразу Remove», повторное приглашение снимает отмену; external commit отменённого устройства и при опубликованном Remove не принимается; TTL Add в эпохах и замена истекающего KeyPackage; лимит листьев; доставка Welcome по `KeyPackageRef` с нарезкой по адресатам и атомарной отметкой одним `UPDATE … RETURNING`, не прерываемой обрывом запроса (при ошибке сборки отметка снимается); бан удаляет недоставленный Welcome; HTTP с long-poll; эмулятор клиентов `cmd/emul`.
- `ds/internal/mlswire`: разбор заголовков `PrivateMessage`/`PublicMessage`, KeyPackage (с capabilities), Welcome (без повторов `KeyPackageRef`), нарезка Welcome; подпись предложений external sender с AAD; 6 фаззеров; golden-векторы OpenMLS в `testdata/openmls` (подписи DS побайтно совпадают с OpenMLS).
- `client/` (Rust, openmls 0.9.2): устройство с политикой S1, привязкой предложений к устройству, проверкой UpdatePath/Update, дельтой, закреплённым external sender, фильтром негодных Add перед commit-ом по образцу проверок openmls (срок, capabilities, расширения листа, ключ подписи и HPKE-ключи, включая перекрёстную коллизию init ↔ encryption); свой принятый commit из потока применяется по побайтному совпадению; `wire.rs` — строгие varint, разбор KeyPackage, подпись external-предложений для тестов; `e2e` (26 проверок), `load` (нагрузка со сверкой состава с DS, сводка), `vectors`; 20 тестов политики + 3 юнит-теста.
- `go test -race` зелёный (30 тестов DS на testcontainers-Postgres + 7 тестов `mlswire`), в том числе на железе тест-сервера через стенд агента (`just remote spikes/04-mls-ds/test`); `cargo test`, `cargo clippy -D warnings`, `cargo deny` — чисто; `golangci-lint` 2.6.2 с `gosec`, `errorlint`, `revive`, `nolintlint` — 0 замечаний.
- Ревью (по два раунда): clean-room — замечания закрыты, кроме подтверждения изоляции автора, которое даётся в описании PR; security — первый раунд 12 находок (1–4 высоких), второй раунд 10 находок (N1 высокая); всё исправлено с регрессионными тестами, кроме N3 и N7 — они не устраняются на стороне DS и записаны в ADR-0018 как ограничения и требования к B02 (см. `REPORT.md` «Безопасность»). Третий раунд: 7 находок (Н1 средняя — перекрёстная коллизия HPKE-ключей); Н1–Н4, Н6, Н7 исправлены с тестами, Н5 — требование к B05. Точечная проверка Н1: П1 (расширения листа), П2 (тесты: все 5 мутаций фильтра ловятся), П3, П4 исправлены; ограничение по сроку пакета у получателя записано в ADR-0018 п. 4.
- Замеры после исправлений: матрица 1 000 входов × 12 сценариев × 3 повтора, вход в группе без ожидающих Add, 2 000 и 4 000 входов, потолок DS без криптографии — `results/`, сводка в `REPORT.md`.

## Сломано / не получилось

- Взаимоблокировка при `-lock=row` из первого раунда (повышение `KEY SHARE` у заявки) внутрипроцессным тестом не воспроизводится; регрессия ловится только `SCENARIOS="сразу, lock row" just load`. Взаимоблокировка второго раунда (N2) ловится `TestJoinRaceWithCommit`.
- DS не может сам проверить, что Remove выполнен (N3), а сверка состава с картой DS возможна только в той же эпохе (N7) — требования к B02 в ADR-0018.
- External commit проверен только синтетически (заголовок, дельта, эпоха) и по умолчанию выключен (флаг DS `-allow-external-commit`; клиент спайка его не делает); настоящий external commit OpenMLS — B02.
- Перестановку устройств в дельте DS не обнаруживает: получатели и новички (сверка с картой DS) — да; процедуры восстановления рассинхрона в спайке нет — B02.
- Стенд — одна машина: при 4 000 входов CPU загружен на ~1 000 %, абсолютные числа для этого масштаба завышены.

## Дальше

- B02: формат `RosterDelta` и AAD предложений, проверки у DS и клиента, восстановление рассинхрона, назначенный коммитер, повтор предложений по эпохам, ротация ключа инстанса (ADR-0018 «Последствия»).

## Технические допущения

- Go-модуль — `go 1.24` (минимум `testcontainers-go` 0.39.0); `pgx/v5` 5.7.6. Транзитивные зависимости закреплены на версиях для Go 1.24: `go get …@latest` для `x/*`/otel поднял бы директиву до 1.26. Схема — один `schema.sql` без миграций (в продукте — goose).
- HTTP-форма упрощена против `docs/protocol/REST.md`: без аутентификации, `device_id` в теле, id группы в пути — hex, байты — base64 в JSON; код лимита — `CHANNEL_MEMBER_LIMIT` и `VALIDATION_FAILED`, как в REST.md, остальные коды DS перечислены в ADR-0018 как предложение для B05. Свой HTTP/1.1-клиент в Rust вместо библиотеки — DS слушает только loopback.
- Basic credential = `device_id`; одно устройство = одна группа в клиенте спайка.
- Обработка Welcome в нагрузке ограничена числом ядер (семафор) и считается без ожидания очереди стенда: на проде у каждого устройства свой процессор.
- Postgres в Docker с данными в tmpfs: замеры не включают задержку диска.

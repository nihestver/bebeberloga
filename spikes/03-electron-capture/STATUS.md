# S3 — спайк захвата экрана в Electron: состояние

Промпт: `docs/prompts/S3-electron-capture.md`. Ветка `feat/S3-electron-capture`. Отчёт — `REPORT.md`, решение — `docs/adr/0024-spike-s3-electron-capture.md` (принято 2026-11-11).

## Сделано

- Стенд на Electron 45.2.3: main-процесс (список источников, обработчик `getDisplayMedia` с кэшем источников, локальный LiveKit 1.13.11, метрики процессов), окна стримера, часов и зрителя; публикация через `livekit-client` 2.23.0 с E2EE кадров.
- Замер задержки «экран → зритель» по метке времени в кадре (`src/main/strip.ts`, тест `just test`): 28 прогонов по 60 с на macOS — окно и весь экран, 720p30 / 1080p30 / 1080p60, H.264, H.265, VP9, с E2EE и без, simulcast, зритель с чужим ключом. Сводка — `results/summary.md`.
- Проверка энкодера без LiveKit (`S3_ENCODER_PROBE=1 just probe`): найдено, почему H.264 через LiveKit кодируется программно.
- macOS без разрешения «Запись экрана»: упакованное приложение со своим идентификатором, запуск через `open`; режим ожидания разрешения (`S3_MODE=permwait`).
- Системный звук на macOS в упакованном приложении с разрешением: работает, стерео 48 кГц без обработки, публикуется с E2EE; в него попадает и звук самого приложения.
- Системный пикер macOS: открывается, обработчик не вызывается, таймаут 10 с; выбор окна в пределах 10 с даёт поток (проверено владельцем вручную).
- Linux Wayland (KDE, виртуальная машина): портал, один источник на вызов, звук системы, публикация с E2EE; режим X11 в сеансе Wayland.
- Размер сборки (`just package`, `results/size-darwin-arm64.json`).
- Вопросы №31–35 в `docs/spec/OPEN-QUESTIONS.md`.
- Ревью clean room: pass с замечаниями, девять замечаний исправлены (лицензии инструментов описаны, придуманное поведение вынесено в вопросы, данные находок сохранены в `results/facts.json`).

## Сломано / не получилось

- Аппаратный H.264 через `livekit-client` на macOS: согласуется профиль `42e01f`, который Chromium кодирует программно. Перестановка профилей через `setCodecPreferences` не помогла; код попытки удалён.
- Системный звук на macOS при запуске из терминала: дорожка приходит завершённой, причина не выяснена.
- Системный звук macOS включает звук самого приложения: на Chromium-пути голоса звонка попали бы в стрим (вопрос №35).
- Экземпляр упакованного приложения один раз завершился через 0,3 с после старта без сообщения и без аварийного отчёта; повторный запуск отработал.
- Упакованное приложение после пересборки с подписью ad hoc теряет выданное разрешение; переключатель в настройках этого не показывает.
- Electron один раз упал в виртуальной машине Linux на второй подряд публикации; не воспроизводилось отдельным прогоном.
- В первой серии замеров около 10 минут что-то закрывало окна стенда; девять прогонов повторены.

## Дальше

- Проверить ограничение `restrictOwnAudio: true` (исключение собственного звука из системного) — S6 или B13. Переключатели стенда для таких проверок читать из аргументов запуска или файла вне бандла, чтобы не пересобирать приложение и не терять разрешение.
- S6: энкодер на Windows с AMD и Intel через `livekit-client`, профиль `42001f` без временных слоёв для H.264, стартовый битрейт.

## Технические допущения

- Спайк — отдельный npm-проект (`package-lock.json`), в корневые `just lint`/`just test` и в CI не входит; проверки — `just check` в каталоге спайка.
- Ключ E2EE — общая строка в коде стенда; LiveKit — в dev-режиме с его стандартными dev-ключами, только loopback. Токены подписывает main-процесс.
- LiveKit для macOS берётся из бутылки Homebrew без установки (`scripts/fetch-livekit.sh`): релизных сборок под macOS у проекта нет. В git бинарник не хранится.
- Интерфейс окон не использует дизайн-систему и i18n: это измерительный стенд.
- `results/raw/` в git не хранится (названия окон машины замера); в git — `results/summary.*`, очищенная сводка `results/facts.json` и размеры сборки.
- Прогоны без шифрования — только сравнительный замер; в продукте режима без E2EE нет.
- CPU считается по приросту процессорного времени процессов (`ps`), GPU на macOS — «Device Utilization %» из `ioreg`.
- `SECURITY-CHANGELOG.md` для спайка не ведётся — прототип.
- Лицензии BlueOak-1.0.0 и CC-BY-4.0 у инструментов сборки разрешены владельцем 2026-11-11 (`LICENSING.md`, строка «только инструменты»).
- Вариант без ключа `NSAudioCaptureUsageDescription` по решению владельца не проверяется; он остаётся в разделе «Не проверено» отчёта.

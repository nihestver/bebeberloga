# S3 — спайк: захват экрана в Electron (Chromium-путь стрима)

Прототип запасного пути публикации стрима из ADR-0008: `desktopCapturer` + `getDisplayMedia` + `livekit-client` с E2EE кадров. Код одноразовый. Отчёт — [`REPORT.md`](REPORT.md), состояние — [`STATUS.md`](STATUS.md), решение — [ADR-0024](../../docs/adr/0024-spike-s3-electron-capture.md).

## Что внутри

| Путь | Что это |
|---|---|
| `src/main/main.ts` | Main-процесс: три окна, список источников, обработчик `getDisplayMedia`, локальный LiveKit, метрики процессов |
| `src/main/scenarios.ts` | Автоматические сценарии: матрица замеров, снимок разрешений и источников, проверка системного звука |
| `src/main/strip.ts` | Формат полосы с меткой времени в кадре |
| `src/renderer/streamer.*` | Окно стримера: сетка источников, пресеты, публикация |
| `src/renderer/clock.*` | Окно-источник: метка времени и счётчик кадров ячейками, движущиеся фигуры, тон 440 Гц |
| `src/renderer/viewer.*` | Окно зрителя: подписка, чтение метки из кадра, статистика приёма |
| `scripts/` | Загрузка LiveKit, сводка прогонов, упаковка, тест формата полосы |
| `results/` | Сводные таблицы; сырые прогоны (`results/raw/`) в git не хранятся — в них заголовки окон машины, где шёл замер |

## Запуск

Нужны Node 22 и `just`. Все команды — из каталога спайка.

```bash
just install
```

```bash
just livekit
```

```bash
just run
```

`just run` открывает три окна. В окне «S3 стример» клик по карточке источника сразу запускает стрим с E2EE; окно «S3 зритель» показывает его и задержку.

Остальные рецепты:

| Рецепт | Что делает |
|---|---|
| `just check` | Проверка типов и тест формата полосы |
| `just matrix` | Серия замеров; параметры — переменные `S3_PRESETS`, `S3_SOURCES`, `S3_CODECS`, `S3_E2EE` (`on,off`; `off` — только для сравнительного замера), `S3_SIMULCAST`, `S3_DURATION` (60 с), `S3_WARMUP` (20 с), `S3_TAG` |
| `just probe` | Разрешения ОС, список источников, пробный захват, поддержка кодеков; с `S3_ENCODER_PROBE=1` — какой энкодер берёт WebRTC без LiveKit |
| `just audio` | Системный звук через `getDisplayMedia` |
| `just summary` | `results/raw/*.json` → `results/summary.md` и `results/summary.json` |
| `just facts` | Очищенная сводка разрешений, энкодеров, звука, пикера и Linux: `results/raw` → `results/facts.json` |
| `just package` | Упакованное приложение в `out/` и размеры сборки |
| `just permwait` | Упакованное приложение ждёт разрешения «Запись экрана», затем проверяет захват и системный звук. После выдачи разрешения приложение не пересобирать: с подписью ad hoc пересборка лишает его разрешения |

Во время `just matrix` не трогай окна и не запускай тяжёлые задачи: окна часов и зрителя не должны перекрываться.

Замеры из отчёта сделаны тремя запусками с параметрами по умолчанию (60 с после 20 с прогрева):

```bash
S3_TAG=mac S3_CODECS=h264,h265 just matrix
S3_TAG=mac S3_PRESETS=1080p60 S3_SOURCES=window S3_CODECS=vp9 just matrix
S3_TAG=mac S3_PRESETS=1080p60 S3_SOURCES=window S3_CODECS=h264,h265 S3_E2EE=on S3_SIMULCAST=on S3_WRONGKEY=1 just matrix
```

Linux: `scripts/linux-run.sh wayland` или `scripts/linux-run.sh x11` (в системном окне выбора выбрать окно «S3 часы»). Упакованное приложение запускается через `open -n -a out/…/S3Capture.app --env S3_MODE=probe --env S3_OUT=<каталог>`: при запуске бинарника из терминала разрешения macOS проверяются у приложения с терминалом.

## Как измеряется задержка

Окно часов рисует в верхней полосе время отрисовки (мс) и счётчик кадров чёрно-белыми ячейками с контрольной суммой. Зритель читает полосу из каждого показанного кадра (`requestVideoFrameCallback`) и вычитает метку из ожидаемого времени показа. Оба окна — на одной машине, часы общие, сети между ними нет: SFU слушает `127.0.0.1`. Метка ставится при отрисовке, до вывода на экран, поэтому в задержку входит и ожидание кадра дисплея у источника.

## Ограничения

- Ключ E2EE статический и общий: ключи из MLS и режим «ключ на участника» — предмет спайка S2.
- Прогоны без шифрования (`S3_E2EE=off`) нужны только для сравнительного замера добавки E2EE. В продукте режима без E2EE нет; ветку без шифрования из `src/renderer/room.ts` в клиент не переносить.
- LiveKit запускается в dev-режиме с его стандартными dev-ключами и слушает только loopback.
- Интерфейс окон не использует дизайн-систему и токены: это измерительный стенд, а не экран продукта.

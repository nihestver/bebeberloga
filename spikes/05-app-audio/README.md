# S5 — спайк: звук приложения и захват видео на трёх ОС

Промпт: [`docs/prompts/S5-app-audio.md`](../../docs/prompts/S5-app-audio.md). Прототип, не продуктовый код. Результаты — [`REPORT.md`](REPORT.md), состояние — [`STATUS.md`](STATUS.md), запуск на стенде — [`STAND.md`](STAND.md).

## Что внутри

Один пакет Cargo, две программы:

- **`s5cap`** — программа захвата: список окон с PID и иконкой, дерево процессов и его аудиоузлы, запись звука в WAV и видео-меток в журнал, разбор записи, самотест.
- **`s5src`** — тестовый источник: окно с бегущей полосой, непрерывный тон, раз в секунду вспышка окна и щелчок одновременно; запускает дочерний процесс со своим тоном.

| ОС | Звук | Видео | Окна и процессы |
|---|---|---|---|
| Windows | WASAPI: process loopback с деревом процессов → система без собственного процесса → loopback устройства вывода | Windows Graphics Capture → DXGI Desktop Duplication → GDI BitBlt | `EnumWindows`, Toolhelp, аудиосессии |
| macOS | ScreenCaptureKit: фильтр по окну или по приложению, исключение собственного процесса | ScreenCaptureKit | ScreenCaptureKit, AppKit, libproc, CoreAudio |
| Linux | PipeWire: узел захвата и линковка узлов нужных процессов; monitor устройства вывода | портал ScreenCast и PipeWire | X11, `/proc`, реестр PipeWire |

## Как устроена проверка

Кто чей звук издаёт, видно по частоте: главный процесс источника — 440 Гц, его дочерний процесс — 880 Гц, посторонний процесс — 1320 Гц, сама программа захвата — 2000 Гц. В звуке приложения должны быть первые два тона и не должно быть двух других.

Пропуски ищутся двумя способами: по меткам времени буферов от ОС и по фазе тона 440 Гц (потерянные сэмплы сдвигают фазу). Рассинхрон звука и видео — разность меток щелчка и первого кадра вспышки по единой монотонной шкале; критерий — 95-й процентиль модуля не больше 40 мс, максимум приводится рядом. Источник пишет и свои метки событий по той же шкале, поэтому задержки звука и видео видны по отдельности.

## Запуск

```bash
just -f spikes/05-app-audio/justfile check
```

```bash
just -f spikes/05-app-audio/justfile trial
```

```bash
just -f spikes/05-app-audio/justfile selftest
```

`check` — форматирование, clippy и тесты анализатора; железо не нужно. `trial` — все сценарии этой ОС с основным прогоном на 30 с. `selftest` — основной прогон 10 минут. Остальные рецепты и оценка нагрузки — в `STAND.md`.

Что нужно ОС:

- **macOS 13+**: программе, из которой запущен `s5cap`, должно быть выдано разрешение «Запись экрана и системного звука».
- **Windows 10 21H2+ и 11**: Rust с целью `x86_64-pc-windows-msvc`, Visual Studio Build Tools.
- **Linux**: PipeWire с менеджером сеанса и `xdg-desktop-portal`; для сборки — компилятор C, `pkg-config`, `libclang-dev`, `libpipewire-0.3-dev`, `libasound2-dev`.

## Файлы прогона

Каталог `out/<прогон>/` в git не хранится: в журналах могут оказаться сведения о машине, где шёл замер.

- `selftest.json` — сводка: стенд, окно, дерево процессов и аудиоузлы, по каждому сценарию — метод, замечания, разбор, проверки. Заголовков окон, имён пользователя и машины, путей в ней нет. Копия сводки каждого зачётного прогона лежит в `results/`.
- `<сценарий>/audio.wav` — стерео 48 кГц float32.
- `<сценарий>/audio-chunks.tsv` — буферы звука: метка первого кадра, время прихода, число кадров, флаги ОС.
- `<сценарий>/video-marks.tsv` — кадры: метка времени, время прихода, размер кадра в физических пикселях, яркость контрольной точки, метод, масштаб экрана (1.25 — это 125 %; 0 — ОС масштаб не сообщила).
- `source-marks.tsv` — моменты вспышек и щелчков по часам источника.
- `source-frames.tsv` — момент отрисовки каждого кадра окна источника: по нему видно, кто теряет кадры — источник или захват.

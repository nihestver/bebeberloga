# B19. Документация для пользователей и администраторов

Запуск: `/prompt B19`. Фаза 5. Каталоги: `docs/admin/`, `docs/user/`, сайт документации.

## Роль
Технический писатель в проекте Bebeberloga. Действуют правила `CLAUDE.md`, тон — `BRAND.md`.

## Входные файлы
- docs/spec/FEATURES.md, FLOWS, SCREENS; docs/admin/CONFIG.md (B16); deploy/README.md (B17)
- docs/spec/ARCHITECTURE.md §4.1, §4.11; docs/adr/0028, 0029; docs/protocol/RETENTION.md

## Задача
Руководство администратора (установка Compose и Helm, конфиг, обновление, бэкапы, TURN, лимиты), руководство пользователя (устройства и ключ восстановления, проверка собеседника, стрим, саундборд), сайт документации (mdBook или Docusaurus — через ADR), RU и EN. В руководстве администратора — раздел «Ответственность оператора» (`deploy/README.md`, ADR-0025): регистрация и приём отчётов по умолчанию, что меняется при их включении. Там же — «Что видит оператор и что хранит сервер» по `RETENTION.md` (ADR-0028): адреса клиентов не пишутся, город по IP выключен, удалённое остаётся в резервных копиях до их ротации, журналы медиасервисов без адресов; и настройка TURN по TLS на 443 (ADR-0029). В руководстве пользователя — «Как сообщить о проблеме»: проверка системы, сохранение отчёта, форма issue, ключи `--self-check`, `--save-report`, `--no-logs` и для тестеров беты `--keep-crash-dumps`. Отдельный раздел «Что видит сеть и оператор и как это уменьшить» (`ARCHITECTURE.md` §4.11, ADR-0029): что закрыто шифрованием, что видит оператор инстанса, что видит провайдер, зачем VPN или прокси и что будет в сети без UDP.

## Критерии готовности
- [ ] Новый администратор по документации поднимает инстанс с нуля (проверка на чистой ВМ).

# S1. Спайк: OpenMLS через FFI

Запуск: `/prompt S1`. Фаза 0. Каталог: `spikes/01-openmls-ffi/`. Результат — прототип и отчёт, а не продуктовый код.

## Роль
Rust-криптограф в проекте Bebeberloga. Действуют правила `CLAUDE.md`.

## Входные файлы
- docs/spec/ARCHITECTURE.md §4 (E2EE), §6.1, §6.4
- docs/adr/0004-e2ee-mls-sframe.md
- docs/protocol/README.md («Уже зафиксировано»)

## Задача
1. Rust-крейт на `openmls` + `openmls_rust_crypto` с ciphersuite 0x0001: создать группу, добавить устройства по KeyPackage, commit, Welcome, application message, external sender (Add/Remove-предложения), exporter-секрет.
2. Обвязка `napi-rs` и вызов из Node 22 / Electron 33 (минимальный скрипт или окно).
3. Проверка переносимости: сборка `uniffi` для Kotlin (Android, aarch64) и Swift (iOS, aarch64) — только компиляция и вызов одной функции в тесте/симуляторе, если доступно.
4. Бенчмарк (`criterion`): группа на 10, 100, 1 000 устройств — время commit добавления одного устройства, время обработки commit получателем, размер сериализованного состояния и Welcome.

## Критерии готовности
- [ ] `cargo test` в каталоге спайка зелёный; Node-скрипт печатает расшифрованное сообщение между двумя «устройствами».
- [ ] `spikes/01-openmls-ffi/REPORT.md`: версии, что собралось/не собралось, таблица замеров, риски, рекомендация.
- [ ] Черновик ADR-00NN «Результаты спайка S1» со статусом «Предложено».

## Ограничения
Ключи только в памяти процесса; никаких сетевых вызовов. Версию `openmls` закрепить точно.

# B6. Сервер: messaging, gateway, files, push

Запуск: `/prompt B06`. Фаза 1. Зависит от B4, B5. Каталоги: `server/internal/{messaging,gateway,files,push}`.

## Задача
1. `messaging`: приём шифртекста с проверкой прав по отправителю, хранение, история с пагинацией по UUIDv7 (вместе с обёрнутыми ключами сообщений), хранение связок ключей истории по эпохам (ADR-0015), удаление — стирание шифртекста, обёрнутого ключа, хинтов и вложений с отметкой об удалении (ADR-0028 п. 3), закрепы (id), read-state, хинты упоминаний — хранение, отметка «у отправителя было право 8», выдача кандидатов после офлайна; сервер хинты не сопоставляет (ADR-0027); индикатор набора.
2. `gateway`: WSS, Identify/Ready, seq, heartbeat, Resume с буфером в Valkey, zstd, fan-out через NATS между репликами, rate limits.
3. `files`: presigned URL в S3 (MinIO), квоты, лимит размера инстанса, удаление при удалении сообщения. Размер blob-а — выровненный (ADR-0028 п. 6); хранилище доступно клиенту по 443/tcp (ADR-0029 п. 1).
4. `push`: реестр устройств, UnifiedPush (desktop-уведомления идут через gateway), payload только с id; FCM/APNs — заглушки за интерфейсом (мобильные после 1.0). Хинты упоминаний модуль `push` не использует (ADR-0027 п. 9). Порядок путей — ADR-0030 п. 6: свой сервер UnifiedPush — основной, FCM — запасной и по умолчанию выключен; других исходящих обращений, кроме перечня ADR-0030 п. 5, модули не делают.

## Критерии готовности
- [ ] Интеграционный тест: два клиента-эмулятора обмениваются сообщениями через gateway, Resume после разрыва досылает пропущенное.
- [ ] Тест: тела запросов и записи в БД не содержат открытого текста (контрольные строки).
- [ ] Тест: после удаления сообщения его шифртекста нет в базе, а blob-а — в хранилище; по базе и журналу запросов нельзя определить, кого упомянули, и связать два упоминания одной цели (ADR-0027, ADR-0028).
- [ ] Линт и тесты зелёные; STATUS.md.

## Задача
1. `server/go.mod`, бинарник `cmd/bebeberloga-server` с подкомандами `serve`, `migrate`, `admin` (заглушка), `logs` (есть с PR #48), конфиг YAML + env, `zerolog`, OpenTelemetry, `/api/v1/health` (версия, состояние зависимостей).
2. Миграции `goose` и запросы `sqlc` для таблиц из ARCHITECTURE §5.3 (имена — по GLOSSARY: `permission_overrides`, а не чужие названия).
3. `internal/identity`: регистрация с подтверждением email, вход, сессии, сброс пароля, устройства (без MLS-логики — она в B5), удаление аккаунта; политика регистрации инстанса (по умолчанию — по приглашениям, ADR-0025 п. 12; журнал без IP-адресов и параметров пути, п. 3). IP-адреса и User-Agent не пишутся ни в базу, ни в сохраняемый кэш; счётчики частоты — в памяти или под HMAC адреса со сроком жизни до 10 минут; город по IP в списке устройств — за настройкой инстанса, по умолчанию выключен (ADR-0028 п. 1–2). Сроки — по `RETENTION.md` §2.1: сессия удаляется после 45 суток без использования (№56); повторный вход на том же устройстве — пароль плюс подпись вызова сервера ключом устройства, для удалённого устройства — `DEVICE_REMOVED` (`CRYPTO.md` §3.9, FLOWS/02); одноразовые токены — подтверждение email, сброс пароля, смена email — живут 1 час (№57). Что стирается и что остаётся при удалении аккаунта и устройства — ответ на №52 и `RETENTION.md`. Открытые записи устройств и историю ключей идентичности сервер отдаёт любому вошедшему пользователю (№66).
4. `internal/community`: сообщества, категории, каналы, пресеты ролей и свои роли, движок прав по PERMISSIONS §3 (включая приватные каналы через «Видеть канал»), приглашения (TTL, лимит), настройка «Новые участники видят историю» (сервер и канал), баны, передача владения, канал системных сообщений, звуки саундборда сообщества и личные звуки (публичные ассеты). Канал создаётся одним запросом вместе с группой чата и первой записью; id канала генерирует клиент (№65); MLS-часть запроса принимает `internal/mls` через интерфейс (B5). Каналы по умолчанию создаёт клиент создателя, сервер их не создаёт. Запись с названием и темой канала — по `CRYPTO.md` §6.8 и ADR-0032; `LockedChannel` и превью приглашения канал не называют (ADR-0026). Запись приглашения удаляется при истечении, исчерпании и отзыве (№49).
5. REST-обработчики генерируются из `docs/protocol/openapi.yaml` генератором из ADR B1 (`//go:generate`, запуск — `just gen`); руками пишется только реализация интерфейсов. Не меняй контракт в коде — меняй `openapi.yaml` и перегенерируй.
6. Интеграционные тесты `testcontainers-go` (Postgres, Valkey); hurl-сценарии в `tools/api/scenarios/`: регистрация → вход → создать сервер → приглашение → вступление.

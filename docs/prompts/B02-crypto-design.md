# B2. Криптографический дизайн: CRYPTO.md

Запуск: `/prompt B02`. Фаза 0. Документ, без кода. Желательно после S1 и S4. Рекомендуется plan mode и ревью субагентом security-reviewer.

## Роль
Криптограф протоколов (MLS, SFrame) в проекте Bebeberloga. Действуют правила `CLAUDE.md`.

## Входные файлы
- docs/spec/ARCHITECTURE.md §4 целиком, §8
- docs/adr/0004, 0005, 0013, 0014, 0015
- docs/spec/FLOWS/01-register.md, 02-new-device.md, 04-invite-join.md, 06-messages.md, 07-voice.md, 09-soundboard.md
- docs/spec/SCREENS/07-auth-and-devices.md, 05-voice-and-stream.md §2 (вкладка «Шифрование», код звонка)
- docs/protocol/MESSAGES.md (B1), отчёты S1 и S4, если готовы

## Задача
Написать `docs/protocol/CRYPTO.md`:
1. MLS-профиль: ciphersuite 0x0001, credential, расширения, external sender, lifetime KeyPackage, ротация эпох (смена состава + раз в сутки), правила DS (commit только на текущую эпоху; сервер никогда не создаёт commit).
2. Идентичность и устройства: ключ идентичности, подпись ключей устройств, подтверждение нового устройства — QR и 6 картинок SAS (вывод из транскрипта), ключ восстановления (формат 8×4 символа, кодировка, Argon2id-параметры, хранение ключа идентичности на сервере в зашифрованном виде).
3. Код безопасности собеседника (12 групп по 5 цифр) и код звонка (6 групп по 5 цифр) — точный вывод.
4. Медиа: вывод per-sender SFrame-ключа из exporter (метка, длина), key index, перекрытие старого ключа 2 с, отдельный трек стрима.
5. Ключи истории (ADR-0015): ключ сообщения и его обёртка ключом истории, смена ключа истории (удаление участника, срок 30 дней, выключенная настройка «Новые участники видят историю»), связка ключей канала для текущей эпохи и кто её обновляет (включая external commit), загрузка истории новым устройством; секреты эпох MLS не передаются.
6. mention-hint, шифрование файлов (XChaCha20-Poly1305 чанками 1 МиБ), локальное хранилище (SQLCipher, ключ в хранилище ОС).
7. Модель угроз (из §4.1) и **формальные инварианты I1…In** с **тестами T1…Tn**, которые обязаны реализовать B3 и B5.
8. Публичный API crypto-core (~40 функций) в виде таблицы: имя, вход, выход, ошибки — для B3.

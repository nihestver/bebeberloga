# Чеклист ревью на заимствования

Применяется к каждому модулю перед тем, как считать его готовым. Ревьюер — человек или отдельный ИИ-агент, не участвовавший в написании кода. Результат — комментарий в PR: «clean-room review: pass» или список нарушений.

## Код и схемы

- [ ] В коде, комментариях, тестах, фикстурах и коммитах нет слов из запретного списка `docs/spec/GLOSSARY.md`.
- [ ] Имена сущностей, полей API, событий gateway и таблиц БД взяты из `docs/protocol/` и `GLOSSARY.md`, а не из чужой публичной номенклатуры.
- [ ] Нет фрагментов, подозрительно похожих на чужой код: нехарактерный стиль, чужие комментарии, магические константы без объяснения, нетипичные для проекта имена.
- [ ] Все новые зависимости перечислены с лицензией; нет зависимостей на SDK и библиотеки оригинального продукта или его клиентов.
- [ ] Реализация соответствует `docs/spec/`, а не «как в известном продукте»; поведение, которого нет в спецификации, вынесено в вопросы, а не додумано.

## Интерфейс и ассеты

- [ ] Тексты интерфейса написаны в тоне `BRAND.md`; нет дословных формулировок чужих продуктов.
- [ ] Цвета — только из `brand/tokens.css`; нет фирменного сине-фиолетового оригинала и его серых тонов.
- [ ] Иконки — Lucide/Tabler/Phosphor или собственные; звуки — собственные; шрифты — Unbounded, Nunito, JetBrains Mono.
- [ ] Скриншоты и макеты в репозитории — только собственного интерфейса.

## Безопасность (для crypto-core, mls, media-engine)

- [ ] Изменение записано в `SECURITY-CHANGELOG.md` модуля.
- [ ] Инварианты E2EE из `CLAUDE.md` не нарушены: сервер и SFU не получают ключей, нет режима без E2EE, push без содержимого.
- [ ] Два ревью на PR.

## Процесс

- [ ] Автор подтверждает, что не обращался к оригиналу во время работы над модулем (или запись есть в `LOG.md` с описанием изоляции).
- [ ] `STATUS.md` модуля обновлён: что сделано, что сломано, что дальше.

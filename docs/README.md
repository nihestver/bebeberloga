# Документация Bebeberloga

| Каталог / файл | Назначение | Кто читает |
|---|---|---|
| [`PLAN.md`](PLAN.md) | Рабочий план (13 разделов): цели, clean room, функции и приоритеты, E2EE-дизайн, архитектура, стек, дизайн, компромиссы, дорожная карта, качество, промпты, риски, источники. Содержит наблюдения за сторонними продуктами | Только контур A. Claude Code его не читает (правило deny в `.claude/settings.json`) |
| [`spec/ARCHITECTURE.md`](spec/ARCHITECTURE.md) | Выжимка разделов 4, 5, 6 и 8 плана для реализации: E2EE, архитектура, стек, стрим, компромиссы. Нумерация разделов совпадает с планом | Все; основной архитектурный вход контура B |
| [`adr/`](adr/README.md) | Принятые решения в формате MADR; новое решение — новый файл | Все; контур B обязан следовать |
| [`cleanroom/`](cleanroom/POLICY.md) | Политика clean room, журнал обращений к сторонним продуктам, чеклист ревью на заимствования | Все |
| [`spec/`](spec/README.md) | Функциональная спецификация: глоссарий, функции, права, потоки (`FLOWS/`), экраны (`SCREENS/`) — единственный вход контура реализации | Контур A пишет, контур B читает |
| [`protocol/`](protocol/README.md) | Транспорт, схемы, MLS-профиль, формат сообщений; заполняется в фазе 0–1 | Контур B |
| [`prompts/`](prompts/README.md) | Промпты A1–A5 (готовы), спайки S1–S6, реализация B1–B20: порядок запуска, статусы, шаблон | Тот, кто запускает Claude Code (`/prompt`, `/next`) |
| [`dev/WORKFLOW.md`](dev/WORKFLOW.md) | Процесс разработки: VSCodium и Claude Code (скиллы, субагенты, hooks), инструменты, локальная среда, тест-сервер, CI/CD, тестирование API | Все |

Планируемые позже: `admin/` (руководство администратора инстанса), остальное в `dev/` (руководство разработчика бота и контрибьютора).

## Как вносить изменения

- Факт о продукте или архитектуре меняется в `PLAN.md` **и** в `spec/ARCHITECTURE.md` (или `spec/FEATURES.md`); если это решение — фиксируется ADR.
- Ссылки «PLAN.md раздел N» в ADR: разделы 4, 5, 6, 8 — это одноимённые разделы `spec/ARCHITECTURE.md`; раздел 3 — `spec/FEATURES.md`; раздел 2 — `cleanroom/POLICY.md`.
- Спецификация (`spec/`) меняется только контуром A; вопросы контура B — в `spec/OPEN-QUESTIONS.md`.
- Любое обращение к стороннему продукту — строка в `cleanroom/LOG.md`.

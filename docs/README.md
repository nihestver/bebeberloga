# Документация Bebeberloga

| Каталог / файл | Назначение | Кто читает |
|---|---|---|
| [`PLAN.md`](PLAN.md) | Полный план разработки (13 разделов): цели, clean room, функции и приоритеты, E2EE-дизайн, архитектура, стек, дизайн, компромиссы, дорожная карта, качество, промпты, риски, источники | Все |
| [`adr/`](adr/README.md) | Принятые решения в формате MADR; новое решение — новый файл | Все; контур B обязан следовать |
| [`cleanroom/`](cleanroom/POLICY.md) | Политика clean room, журнал обращений к оригиналу, чеклист ревью на заимствования | Все |
| [`spec/`](spec/README.md) | Функциональная спецификация — единственный вход контура реализации | Контур A пишет, контур B читает |
| [`protocol/`](protocol/README.md) | Транспорт, схемы, MLS-профиль, формат сообщений; заполняется в фазе 0–1 | Контур B |
| [`prompts/`](prompts/README.md) | Список промптов A1–A5, B1–B20 и шаблон промпта B | Тот, кто запускает ИИ-агентов |
| [`dev/WORKFLOW.md`](dev/WORKFLOW.md) | Процесс разработки и CI/CD: инструменты, настройка Claude Code (hooks, субагенты, скиллы), локальная среда, тест-сервер, GitHub Actions, тестирование API, порядок работ фазы 0 | Все |

Планируемые позже: `admin/` (руководство администратора инстанса), остальное в `dev/` (руководство разработчика бота и контрибьютора).

## Как вносить изменения

- Факт о продукте или архитектуре меняется в `PLAN.md` **и** фиксируется ADR, если это решение.
- Спецификация (`spec/`) меняется только контуром A; вопросы контура B — в `spec/OPEN-QUESTIONS.md`.
- Любое обращение к оригинальному продукту — строка в `cleanroom/LOG.md`.

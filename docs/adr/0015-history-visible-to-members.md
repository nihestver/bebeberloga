# ADR-0015: История канала видна всем, кто видит канал

- Статус: Принято; частично изменено ADR-0019
- Дата: 2026-11-02
- Заменяет: [ADR-0006](0006-history-for-new-members.md)
- Связано: ADR-0004; ADR-0013 (п. 7, 13, 16); `docs/spec/ARCHITECTURE.md` §4.4, §4.7, §8

## Контекст

Владелец продукта решил, что история должна вести себя привычно для пользователей чатов сообществ: новый участник канала и новое устройство пользователя сразу видят всю историю, листают её вверх и ищут по ней, не дожидаясь, пока кто-то из участников будет в сети. ADR-0006 (история по умолчанию не передаётся; пакет за ≤ 30 дней от онлайн-участника) этого не даёт. MLS сам по себе тоже не даёт: новый участник группы не может расшифровать сообщения прошлых эпох.

## Решение

1. История канала, личных сообщений и группового чата доступна каждому, кто сейчас видит канал (право «Видеть канал»): новым участникам, вернувшимся участникам и новым устройствам. По умолчанию — везде.
2. Механизм — **ключи истории** (точный формат описывает B2 в `docs/protocol/CRYPTO.md`):
   - содержимое каждого сообщения и ключи вложений шифруются ключом сообщения; ключ сообщения передаётся в MLS-сообщении и дополнительно хранится на сервере, обёрнутый ключом истории канала;
   - ключ истории — симметричный; он сменяется при удалении участника или устройства из группы и по сроку (по умолчанию раз в 30 дней);
   - набор ключей истории канала («связка») хранится на сервере зашифрованным для текущей эпохи MLS-группы; клиент, который делает commit, обновляет связку для новой эпохи;
   - новый участник или устройство после вступления в группу расшифровывает связку и загружает историю с сервера порциями, как любой участник.
3. Настройка канала «Новые участники видят историю» (право «Управлять каналами», `channel.edit`) включена по умолчанию. Если её выключить, при добавлении участника начинается новый ключ истории и новичок получает только ключи с этого момента. Детали — B2.
4. Отдельная зашифрованная резервная копия истории в 1.0 не нужна: новые устройства получают историю тем же путём. Ключ восстановления остаётся — он нужен, чтобы подтвердить новое устройство без старого.
5. Сервер по-прежнему не получает ни ключей, ни открытого текста.

## Последствия

- Forward secrecy для истории слабее. Тот, у кого есть ключи истории канала (участник или его скомпрометированное устройство), может прочитать всю историю канала, которую хранит сервер. Это осознанная плата за привычное поведение. Новые сообщения после удаления участника ему недоступны: ключ истории сменяется.
- Украденное приглашение даёт доступ ко всей истории каналов, которые видит «@все», как в продуктах без E2EE. Для закрытых обсуждений — приватные каналы.
- Поиск работает по всей истории: клиент индексирует её локально по мере загрузки.
- Сервер хранит к каждому сообщению обёрнутый ключ (десятки байт) и связки ключей истории по каналам.
- Если участника добавляет он сам (external commit, когда никого нет в сети), связку для новой эпохи обновляет первый участник, вышедший в сеть. B2 описывает этот случай.

## Рассмотренные альтернативы

- ADR-0006 — пакет сообщений за ≤ 30 дней от онлайн-участника, по умолчанию выключено. Безопаснее, но не даёт привычного поведения и зависит от того, кто в сети.
- Передавать новичку секреты прошлых эпох MLS — раскрывает больше нужного и ломает модель MLS.
- Хранить историю на сервере открытым текстом — противоречит E2EE (ADR-0004).

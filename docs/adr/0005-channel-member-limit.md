# ADR-0005: Лимит участников канала вместо режима без E2EE

- Статус: Принято
- Дата: 2026-11-02
- Связано: ADR-0004; PLAN.md разделы 1, 4.3, 8, 12

## Контекст

MLS-группа на тысячи устройств дорога при массовых входах и выходах (commit-шторм, размер дерева). Публичные сообщества на 50 000+ участников в одной E2EE-группе не работают. Вариант «публичный канал с серверным ключом» дал бы масштаб ценой отказа от E2EE.

## Решение

- Жёсткий лимит участников канала: по умолчанию **2 000** (≈ 5 000 устройств), настраивается администратором инстанса.
- Сервер отклоняет вход сверх лимита; в UI — «В канале достигнут лимит участников», без упоминания шифрования.
- Режима без E2EE для больших каналов нет и не планируется.
- Для снижения нагрузки: батчинг proposal-ов в «тихих» каналах, ленивые коммиты, спайк 4 (1 000 одновременных входов).

## Последствия

- Сообщества крупнее лимита в 1.0 не поддерживаются; это ограничение продукта, а не скрытое ослабление безопасности.
- Если спайк 4 покажет проблемы — снижается лимит по умолчанию, а не включается серверный ключ.

## Рассмотренные альтернативы

- Серверный ключ для публичных каналов с пометкой в UI: отклонено как нарушение требования «E2EE для всего».
- Сообщение «E2EE не масштабируется дальше»: отклонено, пользователю достаточно факта лимита.

# ADR-0034: Linux — эталон приёмки по текущей LTS Ubuntu Desktop, стрим в 1.0 только в сеансе Wayland

- Статус: Принято 2026-11-25 (владелец)
- Дата: 2026-11-25
- Частично изменяет: [ADR-0008](0008-stream-media-engine.md) — п. 3 (цепочка захвата видео на Linux) и строку последствий «Эталонное железо для приёмки» (Linux)
- Связано: [ADR-0009](0009-platform-minimums.md) (минимумы не меняются), [ADR-0024](0024-spike-s3-electron-capture.md); `docs/spec/ARCHITECTURE.md` §6.5; `docs/spec/FLOWS/08-stream.md`; `docs/spec/SCREENS/05-voice-and-stream.md` §4; вопросы №73 и №74 в `docs/spec/OPEN-QUESTIONS.md`; промпты S5, S6, B12, B13

## Контекст

ADR-0008 и `ARCHITECTURE.md` §6.5 называли эталоном Linux для приёмки «Ubuntu 24.04 с AMD и NVIDIA». Версия, записанная числом, устаревает молча: выходит следующая LTS, а документ продолжает называть прежнюю, и никто не решал, менять её или нет.

Текущая LTS-версия — Ubuntu 26.04. Её штатный рабочий стол работает только на Wayland, сеанса X11 в нём нет. Цепочка захвата из ADR-0008 и §6.5 содержала ветку для X11: XComposite/XShm без портала. На эталоне эту ветку принять негде.

## Решение

1. **Эталон Linux для приёмки — текущая LTS-версия Ubuntu Desktop** со штатным рабочим столом и штатным сеансом, с AMD (VAAPI) и NVIDIA. **На 2026-11-25 это Ubuntu 26.04 LTS.**
2. **Смена эталона — явная правка.** Когда выходит следующая LTS, строка с версией и датой в `ARCHITECTURE.md` §6.5 («Эталонное железо для приёмки») меняется отдельным PR. До этой правки эталоном остаётся записанная версия. Правило при этом не меняется, новый ADR не нужен.
3. **В 1.0 стрим на Linux поддерживается в сеансе Wayland.** Захват видео — xdg-desktop-portal ScreenCast → PipeWire. Захват через XComposite/XShm и любой код захвата, особый для сеанса X11, в 1.0 не входят; клиент только отличает сеанс X11, чтобы показать объяснение (п. 5).
4. **Минимумы ADR-0009 не меняются**: Debian 12+, Ubuntu 22.10+ с PipeWire 0.3.62+ и WirePlumber, уровень 2. На этих системах стрим работает в сеансе Wayland.
5. **В сеансе X11 окно выбора источника объясняет, что стрим работает в сеансе Wayland** (ответ владельца на вопрос №73): окно открывается, вместо сетки — `EmptyState` с объяснением без кнопки, как на macOS без разрешения; описано в `FLOWS/08` и `SCREENS/05` §4.2. Что показывает «Проверка системы» в сеансе X11 — вопрос №74.

## Последствия

- `ARCHITECTURE.md` §6.5 исправлен вместе с этим ADR: строка Linux таблицы «Захват видео» и абзац «Эталонное железо для приёмки». `FLOWS/08` «Начать стрим» и `SCREENS/05` §4.2 дополнены сеансом X11.
- Если фраза про Ubuntu 24.04 есть и в рабочем плане аналитиков, её правит контур A.
- S5 проверяет Linux в сеансе Wayland; сеанс X11 — вне области проверки спайка.
- B12 и S6 не пишут ветку захвата для X11; B13 не делает для Linux сетку окон: в сеансе Wayland источник выбирается через системный портал, в сеансе X11 окно показывает объяснение (`SCREENS/05` §4.2). Клиенту нужно отличать сеанс X11 от Wayland — это единственное, что он знает об X11.
- Пользователи рабочих столов, у которых есть только сеанс X11, в 1.0 остаются без стрима. Linux — платформа уровня 2 (ADR-0009): релиз это не блокирует.
- ADR-0024 не затронут: Chromium-путь на Linux проверялся только на Wayland.

## Рассмотренные альтернативы

- **Оставить в документах конкретную версию без правила.** Эталон устаревает без решения. Отклонено.
- **Считать эталоном последнюю LTS с момента её выхода, без правки документов.** Эталон меняется сам, пока стенд и приёмка ещё на прежней версии. Отклонено: смена — отдельный PR с версией и датой.
- **Оставить цепочку X11 целиком** (портал, затем XComposite/XShm). Код, который нельзя принять на эталоне, попадает в релиз непроверенным. Отклонено.
- **Оставить X11 только через портал.** Тот же код, что на Wayland, но поведение в сеансе X11 всё равно негде принять. Отклонено владельцем в пользу п. 3.
- **Второй рабочий стол с сеансом X11 на стенде приёмки.** Результат получен не на эталоне; стенд усложняется. Отклонено.

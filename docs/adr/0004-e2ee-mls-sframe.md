# ADR-0004: E2EE для всего на MLS + SFrame, стрим без режима отката

- Статус: Принято
- Дата: 2026-11-02
- Связано: PLAN.md разделы 3.0, 4, 6.5, 8

## Контекст

E2EE для всего общения — условие существования проекта. Нужна схема, которая покрывает личные сообщения, каналы, файлы, голос, камеру и стрим, работает для групп из тысяч устройств и совместима с SFU. Отдельно обсуждалось, не отключать ли E2EE для стрима 1080p60 из-за нагрузки.

## Решение

1. **MLS (RFC 9420)** через [OpenMLS](https://github.com/openmls/openmls) — для всех групп: DM, групповой DM, текстовый канал, приватная ветка, звонок (отдельная короткоживущая группа). Ciphersuite v1: `MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519`, credential Basic.
2. **Сервер — Delivery Service**: склад KeyPackages, GroupInfo, сериализация Proposal/Commit по эпохам, external-sender-предложения на вход/выход по правам. Ключей у сервера нет.
3. **Устройства**: пользователь имеет ключ идентичности (Ed25519); каждое устройство — отдельный MLS-клиент, подписанный ключом идентичности; верификация по safety number/QR; ключ восстановления.
4. **Медиа**: LiveKit SFU с E2EE кадров (AES-GCM, SFrame-подход); per-sender ключ выводится из MLS-группы звонка через exporter и ротируется при каждой смене эпохи. Стрим шифруется так же, как камера.
5. **Файлы**: XChaCha20-Poly1305 чанками, ключ в MLS-сообщении, blob в S3.
6. **Стрим — E2EE всегда, одним режимом.** Режима отката на транспортное шифрование нет. При нехватке ресурсов клиент снижает пресет качества (1080p60 → 1080p30 → 720p30), шифрование не отключается.
7. **Push без содержимого**; локальное хранилище — SQLite + SQLCipher; поиск — локальный FTS5.
8. Внешний аудит crypto-core и протокола до релиза 1.0; воспроизводимые сборки клиентов.

## Последствия

- Серверные функции над содержимым (поиск, превью ссылок, automod, индексация) переносятся на клиент или в бота-участника (PLAN.md раздел 8).
- Для стрима недоступны SVC и серверная подстройка качества; вместо них simulcast из двух слоёв и dynacast.
- Шифрование кадров добавляет < 2 мс на кадр и доли процента CPU — дорогим стрим делает кодирование, а не E2EE.
- Один режим проще двух: один путь кода, одно состояние замка в UI.

## Рассмотренные альтернативы

- Double Ratchet / Signal-протокол: не масштабируется на каналы из тысяч устройств.
- Собственный протокол: не аудируем, не стандартизирован.
- Откат стрима на транспортное шифрование при перегрузке: отклонено — экран содержит самое чувствительное содержимое звонка, а сложность двух режимов выше выигрыша.
- Заимствование реализации конкурента: исключено политикой clean room; совместимость с ней не нужна.

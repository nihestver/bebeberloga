# ADR-0002: Сервер на Go, модульный монолит

- Статус: Принято
- Дата: 2026-11-02
- Связано: PLAN.md разделы 5, 6.1

## Контекст

Нужен self-hosted сервер, который администратор ставит одним бинарником или через Docker Compose. Масштаб инстанса — тысячи соединений, не миллионы. Основной язык команды — Go. SFU (LiveKit) тоже на Go.

## Решение

- Сервер — Go 1.23+, модульный монолит: пакеты `internal/{identity,community,messaging,mls,gateway,media,files,push,admin}` с явными интерфейсами, один бинарник `bebeberloga-server` с подкомандами `serve`, `migrate`, `admin`.
- Стек: `net/http` + `chi` (или Connect-RPC), `pgx`, `sqlc`, `goose`, `nats.go`, `valkey-go`, `zerolog`, OpenTelemetry.
- Хранилища: PostgreSQL 16, Valkey 8, NATS JetStream (fan-out между репликами gateway), S3-совместимое хранилище (MinIO или Garage), LiveKit + coturn.
- Горизонтальное масштабирование: gateway за NATS, stateless API; MLS-очередь сериализуется по group_id.

## Последствия

- Один язык и одна система сборки для сервера и медиа.
- Точка расширения для выноса модулей в сервисы и для будущей федерации остаётся, но в 1.0 не реализуется.
- При росте таблицы сообщений — вынос в ScyllaDB за интерфейсом репозитория.

## Рассмотренные альтернативы

- Стек оригинала (Elixir/Erlang для realtime, Python/Rust для API, ScyllaDB): заточен под одно развёртывание на сотни миллионов пользователей; для self-hosted инстанса усложняет эксплуатацию и не даёт преимуществ. Clean room касается кода, а не языка, поэтому повторять стек не требуется.
- Rust на сервере: выше порог входа и сроки; Rust остаётся для crypto-core и media-engine.
- Если шлюз упрётся в число WebSocket-соединений — вынести его в отдельный сервис (в том числе на Elixir), не трогая остальное.

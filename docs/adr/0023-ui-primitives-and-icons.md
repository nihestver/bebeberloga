# ADR-0023: Дизайн-система клиента — примитивы доступности React Aria Components, иконки Lucide

- Статус: Принято 2026-11-07 (владелец, при одобрении плана B08)
- Дата: 2026-11-07
- Связано: `docs/spec/SCREENS/COMPONENTS.md` §7–§8; `docs/prompts/B08-design-system.md` п. 3–5; [ADR-0003](0003-licenses.md), [ADR-0007](0007-desktop-shell-electron.md), [ADR-0013](0013-ui-spec-decisions.md) п. 8; `LICENSING.md`, `ATTRIBUTION.md`; `docs/spec/ARCHITECTURE.md` §6.1, §6.4

## Контекст

Дизайн-система (`clients/web/src/ui`, B08) реализует каталог `COMPONENTS.md`. Два выбора в нём оставлены B08 и требуют ADR с проверкой лицензий:

- **Примитивы доступности.** §8 требует, чтобы всё работало с клавиатуры: меню с подменю, выпадающий выбор с поиском, вкладки, модальные окна с ловушкой фокуса, подсказки при фокусе, списки с ролями `tree`/`list`/`grid`. Писать это с нуля — значит повторять правила WAI-ARIA и ловить расхождения браузеров; нужна библиотека поведения без готовых стилей (вид задают наши токены).
- **Иконки.** §7: «линейные 20 px с толщиной 1.75, скруглённые концы, генерируется одной библиотекой под свободной лицензией. Не перерисовывать иконки сторонних продуктов». `ATTRIBUTION.md` называл кандидатов: Lucide, Tabler, Phosphor.

Версии и лицензии ниже сверены с реестром npm 2026-11-07 и с файлами установленных пакетов.

## Решение

### 1. Примитивы доступности — React Aria Components

`react-aria-components` 1.22.1 (Adobe, **Apache-2.0**; тянет `react-aria` 3.53.1 и `react-stately` 3.51.0 той же лицензии). Компоненты дизайн-системы — тонкие обёртки: поведение и ARIA-разметка от библиотеки, вид — CSS Modules и токены.

Что решило выбор (проверено по типам пакета):

- меню с подменю и настраиваемой задержкой открытия (`SubmenuTrigger delay`; спецификация требует 150 мс);
- `Autocomplete` — поиск внутри выпадающего списка (`Select` с числом вариантов больше 10);
- `Table` с сортировкой, `GridList` и `Tree` с навигацией стрелками — роли `grid`/`tree` из §8 для списков каналов, участников и сообщений (B09, B10);
- `ColorSwatchPicker`, `ColorArea`, `ColorSlider`, `ColorField` — для `ColorSwatches`;
- состояния «наведение», «нажатие», «фокус с клавиатуры» отдаются data-атрибутами (`data-hovered`, `data-pressed`, `data-focus-visible`) — стили всех состояний из §2 привязаны к ним, в том числе нажатие с клавиатуры;
- встроенные тексты для экранных дикторов переведены, русская локаль (`ru-RU`) есть; локаль задаёт `I18nProvider`.

Ограничения, принятые сознательно:

- Готового контекстного меню по правому клику нет: `Menu/Context` открывает `Popover` + `Menu` в точке клика собственной обёрткой (`clients/web/src/ui/Menu`).
- Уведомления (`Toast`) в 1.22 экспортируются с префиксом `UNSTABLE_`. `Toast` дизайн-системы использует их за собственным интерфейсом; при смене API меняется один файл.
- Закрытие по `Esc` отдано собственному диспетчеру (`clients/web/src/ui/shortcuts`): порядок из `SHORTCUTS.md` («Порядок обработки `Esc`») задаётся типом слоя, а не порядком открытия.

### 2. Иконки — Lucide

`lucide-react` 1.70.0, **ISC**; часть иконок происходит из проекта Feather и несёт уведомление MIT (файл `LICENSE` пакета). Обе лицензии — в списке разрешённых (`LICENSING.md`).

- Размер и толщина линии задаются параметрами: обёртка `Icon` рисует 20 px с линией 1.75 px (`nonScalingStroke`), концы и соединения скруглены в самом наборе.
- Экраны берут иконку по смысловому имени из `clients/web/src/ui/icons/icons.ts` (`icons.micOff`, `icons.textChannel`), а не по имени в библиотеке: замена библиотеки не затронет экраны. Перечень покрывает минимум из §7.
- В набор импортируются только предметные иконки. Логотипов и знаков сторонних продуктов среди них нет; добавлять такие запрещено (clean room).

### 3. Сторонняя библиотека иконок и собственные ассеты — разные правила

ADR-0013 п. 8 («звуки, встроенные аватары и иконки — собственные или под свободной лицензией, CC0-1.0 или CC-BY-SA-4.0, с указанием в REUSE.toml») относится к **ассетам, которые лежат в репозитории**. Lucide под него не подпадает и ему не противоречит:

| | Сторонняя библиотека иконок | Собственные ассеты |
|---|---|---|
| Что | `lucide-react` | Встроенные аватары `design/avatars/`, иконки, которых нет в библиотеке, `design/icons/` |
| Где лежит | npm-зависимость; файлов иконок в репозитории нет | Файлы SVG в репозитории |
| Правило | «Разрешённые лицензии зависимостей» в `LICENSING.md` (ISC разрешена) | ADR-0013 п. 8; лицензия и авторство — по `LICENSING.md`, построчно — в `ATTRIBUTION.md` |
| Учёт | Версия в `clients/web/package.json`, проверка `just lint-licenses` | Строка в `ATTRIBUTION.md` в том же коммите, что и файл (`just attribution`) |

Этот ADR лицензию собственных аватаров и иконок не определяет: она задана в `LICENSING.md`.

Собственные иконки рисуются в том же формате, что библиотечные (сетка 24, линия `currentColor`, скруглённые концы), и подключаются через тот же `icons.ts`. Чужие иконки не перерисовываются: собственная иконка появляется, только когда нужного изображения в библиотеке нет (на 2026-11-07 — `soundboard` и `bold`).

Аватары и собственные иконки лежат в `design/`, а не в `clients/web/src/ui/` (как предлагал промпт B08): ими будут пользоваться и мобильные клиенты. Web-клиент берёт их оттуда при сборке (алиас `@design`). Список id встроенных аватаров — контракт между клиентами (`docs/protocol/`).

### 6. Лицензии транзитивных зависимостей

`just lint-licenses` проверяет всё дерево npm (`clients/web/scripts/check-licenses.mjs`). Три лицензии из дерева в списке `LICENSING.md` пока не названы; все разрешительные:

| Лицензия | Пакеты | Попадает в сборку клиента |
|---|---|---|
| 0BSD | `tslib` (через `react-aria` → `aria-hidden`) | да |
| BlueOak-1.0.0 | `glob`, `minimatch`, `minipass`, `lru-cache`, `path-scurry` | нет, инструменты Storybook |
| CC-BY-4.0 | `caniuse-lite` (таблицы поддержки браузеров, данные) | нет, инструменты сборки |

Скрипт пропускает их отдельным списком «ждут строки в `LICENSING.md`» и отличает зависимости сборки от инструментов. Добавить их в `LICENSING.md` или отказаться от пакетов — решение владельца; новая лицензия вне списков валит проверку.

## Последствия

- `ATTRIBUTION.md`: абзац об иконках интерфейса теперь называет Lucide и этот ADR; собственные иконки и аватары записываются построчно.
- Экраны B09–B13 используют только компоненты `clients/web/src/ui` и иконки из `icons.ts`; прямой импорт `react-aria-components` в экранах допустим для коллекций (`GridList`, `Tree`), которых в каталоге нет.
- `react-aria-components` — заметная часть сборки. Для Electron это не критично; для веб-доступа размер проверяется в B09.
- Обновление мажорной версии библиотеки примитивов или иконок — отдельная PR с прогоном тестов клавиатуры и доступности.

## Рассмотренные альтернативы

- **Radix UI** (`radix-ui` 1.8.1, MIT). Есть готовое контекстное меню, диалог, вкладки, слайдер. В составе 1.8.1 нет поля выбора с поиском, таблицы, списков с ролями `grid`/`tree` и выбора цвета — их пришлось бы добирать другими библиотеками или писать самим. Отклонено.
- **Base UI** (MIT): на момент выбора в npm — кандидат в релизы (`1.0.0-rc.0`). Отклонено как нестабильное.
- **Собственные примитивы**: полный контроль, но объём и риск ошибок доступности несоразмерны задаче. Отклонено.
- **Tabler Icons** (`@tabler/icons-react` 3.50.0, MIT): подходит по стилю; по описанию набора в нём есть раздел логотипов сторонних продуктов (в пакете не проверялось) — для clean room это лишний риск случайного импорта. Отклонено.
- **Phosphor** (`@phosphor-icons/react` 2.1.10, MIT): по описанию набора толщина линии задаётся фиксированными начертаниями (в пакете не проверялось), значение 1.75 не задать. Отклонено.

# ADR-0001: Разработка по методу clean room

- Статус: Принято
- Дата: 2026-11-02
- Связано: PLAN.md раздел 2; `docs/cleanroom/POLICY.md`

## Контекст

Продукт должен функционально и структурно повторять известную закрытую платформу общения. Копирование её кода, минифицированных бандлов, ассетов, текстов интерфейса, схем API и дизайна создаёт риск претензий по авторскому праву; похожий внешний вид — риск по trade dress и товарным знакам.

## Решение

1. Два контура с «стеной»: **A — аналитика** (наблюдает публичное поведение продукта как пользователь, читает публичную справку и инженерные блоги, пишет спецификацию своими словами) и **B — реализация** (видит только спецификацию в `docs/`, RFC и документацию открытых библиотек).
2. Контур B не открывает оригинальный продукт, его документацию для разработчиков и репозитории, не использует его код и ассеты даже под свободной лицензией, не употребляет слова из запретного списка `docs/spec/GLOSSARY.md`.
3. При работе одного человека: сначала целиком пишется спецификация, потом начинается реализация; к оригиналу не возвращаются; каждое обращение к оригиналу фиксируется в `docs/cleanroom/LOG.md`.
4. При работе с ИИ-агентами стена воспроизводится промптами: промпты контура A и B разделены (`docs/prompts/`), `CLAUDE.md` — context pack контура B.
5. Обязательно отличаются от оригинала: название, логотип, звуки, палитра, иконки, шрифт, тексты интерфейса, публичный API и имена полей.
6. Допустимо воспроизводить: паттерны раскладки, поведение функций, горячие клавиши как идею, модель ролей как концепцию, Markdown-подмножество, общеизвестные протокольные идеи (WebSocket-шлюз с resume, SFU, MLS).
7. Инженерные публикации конкурента можно использовать как источник архитектурных принципов (вход контура A), но не кода и не протоколов.

## Последствия

- Спецификация пишется до кода и становится единственным входом реализации; это удлиняет фазу 0.
- Нужны журнал, чеклист ревью на заимствования и ревью-промпт после каждого модуля.
- Совместимость с API оригинала не является целью.

## Рассмотренные альтернативы

- Реализация «по памяти» без спецификации — быстрее, но нет доказуемой независимости.
- Форк существующего открытого аналога — противоречит требованию полного E2EE и собственной архитектуры.

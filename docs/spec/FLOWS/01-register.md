# 01. Регистрация и первый вход

**Предусловия**: политика инстанса «открытая» или «по приглашению» (FEATURES 3.8).

1. **П** открывает клиент → экран входа (`SCREENS/07` §1). Нажимает «Зарегистрироваться».
2. **П** заполняет email, имя пользователя, пароль, ставит галочку правил. **К** проверяет имя на уникальность запросом `GET /users/availability` с задержкой 400 мс после ввода.
3. **П** нажимает «Создать аккаунт». **К** отправляет форму; **С** создаёт аккаунт в состоянии `pending_email`, отправляет письмо.
   - Ошибки: имя занято (гонка) → ошибка под полем; email уже используется → «На этот адрес уже есть аккаунт. Войти?»; инстанс закрыт → экран «Регистрация закрыта»; лимит запросов → «Слишком много попыток, подожди минуту».
4. **К** показывает «Проверь почту». **П** переходит по ссылке → **С** активирует аккаунт; **К** (по событию или опросу каждые 5 с) переходит дальше. Повторная отправка — не чаще раза в 60 с.
5. **К** генерирует ключ идентичности пользователя и ключ первого устройства, публикует открытые ключи и пачку KeyPackage (B2). Ошибка публикации → повтор с экспоненциальной паузой, текст «Готовим ключи…» остаётся; через 30 с — «Медведь споткнулся. Пробуем ещё раз» и кнопка «Повторить».
6. **К** генерирует ключ восстановления и показывает его (`SCREENS/07` §5). **П** сохраняет, ставит галочку, проходит проверку двух групп. Неверные группы → «Не совпало, посмотри на ключ ещё раз» (ключ снова виден по кнопке «Показать ключ»).
7. **П** выбирает аватар из набора и отображаемое имя (можно пропустить).
8. **К** открывает домашний экран с пустыми состояниями.

**Что видят другие**: ничего, пока П не добавит друзей или не вступит на сервер.

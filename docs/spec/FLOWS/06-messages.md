# 06. Сообщения

## Отправка

1. **П** набирает текст, нажимает `Enter`. **К** генерирует UUIDv7 сообщения (если сообщение пролежит в очереди неотправленных дольше 30 сут, при отправке **К** присвоит ему новый UUIDv7 — сервер не принимает `id` старше 30 сут от времени приёма), сразу показывает его в ленте в состоянии «отправляется» (`SCREENS/08` §10).
2. **К** шифрует сообщение ключом сообщения, оборачивает его ключом текущего поколения ключа истории (ADR-0020) и отправляет `SendMessage{group, ciphertext, mention_hints, attachments_meta}`.
3. **С** проверяет права (`chat.post`; для вложений — `chat.upload`), отмечает на сообщении, есть ли у отправителя `chat.ping_all` (`PERMISSIONS.md`, ADR-0027), сохраняет шифртекст, рассылает `MessageCreated`, отправляет push без текста.
4. **К** переводит сообщение в «отправлено». Ошибки: нет сети — очередь и повтор при восстановлении; `PERMISSION_DENIED` — «не отправлено» с причиной; поколение ключа истории устарело (`HISTORY_GENERATION_MISMATCH`) — **К** догоняет commit-ы, шифрует заново и повторяет автоматически (до 3 раз); смена эпохи без смены поколения повтора не требует.
5. **Д**: сообщение появляется в ленте; если канал не открыт — канал выделяется. Упомянут ли пользователь, решает **К** Д по хинтам сообщения — сервер этого не знает (ADR-0027); если упомянут — бейдж упоминаний и системное уведомление (`SCREENS/10` §4.3).

## Упоминания после офлайна

1. При подключении **К** получает в `Ready` по каждому каналу число непрочитанных сообщений-кандидатов: с хинтами или с «@все» / «@здесь».
2. **К** запрашивает кандидатов — id, поколение ключа истории, хинты и отметки, без шифртекста, — вычисляет хинты своего id и своих ролей и считает совпадения с учётом настроек уведомлений (`SCREENS/10` §4). «@здесь» засчитывается, только если сообщение пришло, пока устройство было на связи; совпадение с ролью и «@все» — только если сервер отметил, что у отправителя было право 8.
3. Пока идёт подсчёт, канал показывает обычный бейдж непрочитанного; затем — число упоминаний. Если ключа поколения у устройства ещё нет, подсчёт для этих сообщений откладывается до его прихода.

## Ответ, правка, удаление, реакции

- **Ответ**: как отправка, плюс `reply_to` (id); цитата рендерится клиентом из локально расшифрованного оригинала; если оригинала нет — «Исходное сообщение недоступно».
- **Правка**: новое зашифрованное сообщение `edit{target_id, new_body}`; **К** у всех подменяет текст и ставит «(изменено)». Править можно только своё; срок — без ограничения.
- **Удаление**: `DeleteMessage{id}` → **С** стирает шифртекст, обёрнутый ключ сообщения, хинты и blob-ы вложений, хранит только отметку об удалении (ADR-0028), рассылает `MessageDeleted`; у всех сообщение исчезает без следа; в ответах на него вместо цитаты показывается «Исходное сообщение удалено». Вместе с командой **К** удаляющего — автора или модератора — передаёт id правок этого сообщения; **С** стирает те из них, автор которых — автор удалённого сообщения, остальные id не трогает. Реакции остаются: текста в них нет.
- **Реакция**: малое зашифрованное сообщение `reaction{target_id, emoji, on|off}`; агрегация на клиенте; оптимистичное отображение.

## Удаления после офлайна

1. Отметку об удалении **С** хранит, пока существует канал.
2. Всю ленту вернувшееся устройство не сверяет: **К** забирает отметки об удалении, появившиеся с момента его последней синхронизации, и убирает эти сообщения у себя. Команды удаления из истории (`DeleteBody`) **К** обрабатывает, когда догоняет ленту.

## Вложения

1. **П** добавляет файлы (до 10 за раз; лимит размера — инстанс; раскладка в ленте — `SCREENS/08` §4). Превью в поле ввода.
2. При отправке **К** для каждого файла генерирует случайный ключ, дополняет файл до выровненной длины и шифрует его (потоково, кусками; ADR-0028), загружает blob (`PUT /files`), получает id; метаданные (имя, размер, тип, размеры изображения, миниатюра 64 px в зашифрованном виде, ключ файла) кладёт в зашифрованный конверт сообщения.
3. Прогресс в ленте: «Шифруем и отправляем… N %»; отмена — удаление blob и сообщения.
4. **Д**: **К** показывает `Skeleton` нужного размера, скачивает blob, расшифровывает, показывает. Ошибка расшифровки — плашка «Файл повреждён или ключ недоступен».

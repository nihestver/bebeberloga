# 04. Приглашение и вступление

## Создать приглашение

1. **П** (право 5) открывает «Пригласить» (`SCREENS/06` §4). **К** запрашивает существующую действующую ссылку пользователя для этого канала или создаёт новую `CreateInvite{channel, ttl=7d, max_uses=∞}`.
2. **П** копирует ссылку или нажимает «Пригласить» у друга — **К** отправляет другу ЛС с карточкой приглашения.
3. «Настроить ссылку» → новая ссылка с выбранными параметрами; старая продолжает действовать до истечения.

## Вступить

1. **Д** (приглашённый) открывает ссылку или вставляет её в мастер. **К** запрашивает `GET /invites/{code}` → превью (`SCREENS/06` §2.2).
   - Ошибки: истекла/отозвана, лимит использований, бан, лимит участников канала, приглашения приостановлены.
2. **Д** нажимает «Принять приглашение». **С** добавляет участника с ролью «@все», увеличивает счётчик использований, рассылает `MemberJoined`.
3. **С** как external sender отправляет Add-предложения для всех устройств Д во все MLS-группы каналов, которые Д видит; commit в каждой группе делает онлайн-участник, которого назначает сервер (ADR-0018 п. 7). Пока commit не прошёл, у Д канал показывает `Skeleton` и строку «Подключаемся к каналу…», а поле ввода неактивно (`SCREENS/08` §1, §8). Если в канале сейчас никого нет в сети, Д ждёт, пока кто-нибудь появится: войти без участника клиент в 1.0 не может (ADR-0019). Под строкой — пояснение «Подключимся, как только кто-нибудь из участников появится в сети».
4. После commit клиент, который его сделал, обновляет связку ключей истории для новой эпохи. **К** Д расшифровывает связку и подгружает историю канала с сервера целиком, порциями по мере прокрутки (ADR-0015). Если в канале выключено «Новые участники видят историю», Д видит только сообщения после входа; более ранние не показываются.
5. **К** Д открывает канал из приглашения. **Все** видят системное сообщение «<Д> присоединился(-ась) к серверу» в канале системных сообщений (по умолчанию первый текстовый).

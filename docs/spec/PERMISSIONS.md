# Права и роли v1.0 (A4)

Собственная модель прав Bebeberloga: имена, коды и правила вычисления придуманы для проекта. Права применяются **сервером** к метаданным и к составу MLS-групп. Сервер выступает Delivery Service и external sender: он отправляет только **предложения** Add/Remove, commit делают устройства участников (ADR-0004). Содержимое сообщений сервер не видит, поэтому всё, что требует чтения текста, делается на клиенте.

Коды прав в API и Protobuf имеют вид `<область>.<действие>`. Они хранятся как список строк, а не как битовая маска.

## 1. Базовые права

Базовых прав 15 (ADR-0013 п. 2): к двенадцати функциональным добавлены три структурных права («Видеть канал», «Приглашать», «Управлять сервером»), без которых невозможны приватные каналы, приглашения и настройки.

| # | Право (UI) | Код | Что разрешает | Где применяется | Уровень |
|---|---|---|---|---|---|
| 1 | Управлять сервером | `community.admin` | Право администратора: всё из 3–15 во всех каналах, которые участник видит, плюс название, иконка, история по умолчанию, канал системных сообщений, звуки саундборда, приостановка приглашений | Сервер | Сервер |
| 2 | Видеть канал | `channel.see` | Видеть канал в списке и **быть участником его MLS-группы**. При выдаче права сервер предлагает Add для устройств пользователя, при снятии — Remove | Сервер + MLS | Сервер, канал |
| 3 | Управлять каналами | `channel.edit` | Создавать, переименовывать, переставлять и удалять каналы и категории; менять тему, медленный режим (S), настройку «Новые участники видят историю»; делать канал приватным (вместе с 4); обновлять ключи канала | Сервер | Сервер, категория, канал |
| 4 | Управлять ролями | `role.edit` | Создавать и менять роли **младше своей старшей** (раздел 3), выдавать и снимать их; выдавать можно только права, которые есть у себя | Сервер | Сервер |
| 5 | Приглашать | `invite.make` | Создавать ссылки-приглашения и приглашать друзей | Сервер | Сервер, канал |
| 6 | Писать | `chat.post` | Отправлять сообщения и реакции, создавать ветки (S) | Сервер принимает или отклоняет зашифрованное сообщение по отправителю | Сервер, категория, канал |

| 9 | Управлять сообщениями | `chat.moderate` | Удалять чужие сообщения (tombstone), закреплять и откреплять, убирать чужие реакции | Сервер | Сервер, категория, канал |

| 11 | Подключаться | `voice.join` | Входить в голосовой канал: получить токен SFU и вступить в MLS-группу звонка | Сервер (media) | Сервер, категория, канал |

| 14 | Саундборд | `voice.sounds` | Проигрывать звуки сервера, свои и стандартные. Загружать и удалять звуки сервера можно только с правом 1 | Сервер: принимает команду `PlaySound` от участника голосового канала, проверяет кулдаун и рассылает событие (FLOWS/09) | Сервер, категория, канал |
| 15 | Заглушать других | `voice.moderate` | Серверно выключить микрофон или звук участнику (M). Отключить от голосового канала и перенести в другой канал (S) | SFU (блокировка трека) | Сервер, категория, канал |

Неявные правила:
- **Владелец** имеет все права, и их нельзя ограничить переопределениями. Приватный канал он видит, только если добавит в него себя (раздел 3).
- Права **не дают** доступа к содержимому. Ни модератор, ни владелец, ни администратор инстанса не читают канал, в MLS-группе которого нет их устройства.
- Нельзя действовать против участника с равной или старшей ролью: выгнать, забанить, сменить роли, заглушить.

## 2. Пресеты ролей

Создаются вместе с сервером. Порядок старшинства в 1.0 фиксированный: Владелец > Администратор > Модератор > свои роли > @все. Перестановка ролей и полная иерархия — C (FEATURES 3.3).

| Право | Владелец | Администратор | Модератор | @все (каждый участник) |
|---|---|---|---|---|
| Управлять сервером | ✓ | ✓ | — | — |
| Видеть канал | ✓ | ✓ | ✓ | ✓ |
| Управлять каналами | ✓ | ✓ | — | — |
| Управлять ролями | ✓ | ✓ | — | — |
| Приглашать | ✓ | ✓ | ✓ | ✓ |
| Писать | ✓ | ✓ | ✓ | ✓ |
| Отправлять вложения | ✓ | ✓ | ✓ | ✓ |
| Упоминать всех | ✓ | ✓ | ✓ | — |
| Управлять сообщениями | ✓ | ✓ | ✓ | — |
| Выгонять и банить | ✓ | ✓ | ✓ | — |
| Подключаться | ✓ | ✓ | ✓ | ✓ |
| Говорить | ✓ | ✓ | ✓ | ✓ |
| Стримить | ✓ | ✓ | ✓ | ✓ |
| Саундборд | ✓ | ✓ | ✓ | ✓ |
| Заглушать других | ✓ | ✓ | ✓ | — |

«@все» — встроенная роль, которая есть у каждого участника. Отдельной роли «Участник» нет. Свои роли (M, FEATURES 3.3) имеют название и набор прав из таблицы 1. Цвет роли и показ отдельной группой в списке участников — C.

## 3. Вычисление прав

1. **База.** Права участника на сервере — объединение прав всех его ролей, включая «@все». С правом «Управлять сервером» участник проходит проверки 3–15 во всех каналах, которые видит.
2. **Приватный канал.** Канал виден только тем, кому явно разрешено «Видеть канал». Это касается и владельца с администраторами: их устройства не попадают в MLS-группу автоматически. Владелец и администратор видят приватный канал в списке как «🔒 закрытый для тебя» и могут добавить себя. Участники канала увидят это системным сообщением.
3. **Переопределения.** В 1.0 (M) поддерживается одно: «Видеть канал» для роли или участника на уровне канала. Этого достаточно для приватных каналов. Полные переопределения всех прав по категориям и каналам с тремя состояниями (запретить / наследовать / разрешить) — S. Их порядок: «@все» → объединение запретов ролей → объединение разрешений ролей → конкретный участник.

## 5. Ошибки и отображение

- Элементы, на которые нет права, **не показываются**: пункты меню, кнопки в шапке, разделы настроек. Если элемент важен для понимания (поле ввода, кнопки звонка), он показывается неактивным с подсказкой причины.
- Сервер всё равно проверяет каждое действие. Ошибка `PERMISSION_DENIED` содержит поле `missing_permission` (B1). Клиент показывает `Toast` «Не хватает права «<название>»».
- Изменение прав приходит событием gateway `PermissionsUpdated`, и интерфейс перерисовывается без перезагрузки.

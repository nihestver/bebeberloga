# Функциональная спецификация

Единственный вход контура реализации (см. `docs/cleanroom/POLICY.md`). Пишется контуром A своими словами по наблюдаемому поведению, без копирования текстов, стилей и схем сторонних продуктов.

## Состав и статус

| Файл | Что содержит | Промпт | Статус |
|---|---|---|---|
| [`GLOSSARY.md`](GLOSSARY.md) | Термины интерфейса и кода, правила именования, запретный список | A5 | Готов (черновик 1) |
| [`FEATURES.md`](FEATURES.md) | Инвентарь функций с приоритетами M/S/C и влиянием E2EE | A1 | Исходная версия из плана; нужно уточнить наблюдаемое поведение каждой M-функции |
| `FLOWS/` | Пользовательские сценарии, по файлу на поток: регистрация, добавление устройства, создание сообщества, приглашение, DM, звонок, стрим (выбор источника, качество, завершение), soundboard | A2 | Не начат |
| `SCREENS/` | Текстовые описания экранов: зоны, элементы, состояния, адаптивность; без цветов и иконок оригинала | A3 | Не начат |
| `PERMISSIONS.md` | 12 базовых прав v1.0, пресеты ролей, таблица «действие → права» | A4 | Не начат |
| `OPEN-QUESTIONS.md` | Вопросы контура B к спецификации | — | Создаётся при первом вопросе |

## Правила написания

- Для каждой функции: что видит пользователь, что происходит при ошибке, какие состояния у элементов, что меняется для других участников.
- Формулировки — свои; тексты интерфейса — в тоне `BRAND.md`.
- Никаких ссылок на оригинальный продукт, его справку и скриншоты: контур B этот каталог читает целиком.
- Приоритет функции меняется только через ADR.

## Базовые права v1.0 (для `PERMISSIONS.md`)

Управлять каналами · управлять ролями · управлять сообщениями · кик и бан · писать · отправлять вложения · упоминать всех · подключаться к голосу · говорить · стримить · использовать soundboard · заглушать других. Пресеты ролей: владелец, администратор, модератор, участник.
